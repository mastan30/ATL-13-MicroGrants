Notebook Summary: Community Economic Resilience & Micro-Grants

Detailed Overview of What We Are Building

We are building a data foundation to make a case for micro-grant interventions using a network-based approach. Instead of just ranking businesses by distress, this project models a real commercial corridor as a property graph in BigQuery. The goal is to allow an agent to argue for a grant on the strength of what it protects downstream—for example, identifying if a distressed business is a critical supplier to other healthy businesses, meaning its closure would cause a cascading loss of jobs.

Summary of the Data

  • Real Businesses: Every node represents a real registered business in San Francisco, including its name, address, coordinates, and industry code.
  • Real Corridors: The businesses are grouped using San Francisco's official "business_corridor" designations (e.g., Central Market, North Beach).
  • Real Financial Connections: Connections regarding which bank lent to which business (and which loans were charged off) come from the Small Business Administration's loan records.
  • Modeled Connections: Supplier and foot-traffic relationships are modeled using industry-level average intensities published by the Bureau of Economic Analysis, applied to local pairs of businesses.

Summary of the Fields

  • Node Fields (Businesses): id, name (dba_name), kind (self_reported_naics_code), jobs, and distress.
  • Edge Fields (Connections): source_id (where the connection starts), target_id (where the connection ends), and kind (the type of relationship, like "supplies" or "footfall").
  • Geographic Fields: business_corridor, which groups the businesses.

Summary of the Graphs Created

The project uses BigQuery Property Graphs (queried with GQL) overlaid on standard relational tables:

  • Node Tables: Contain the individual entities (the businesses) and their properties.
  • Edge Tables: Define the directed relationships between nodes (e.g., Business A supplies Business B).
  • Example Graph (ToyBlock): A sample graph is created to demonstrate graph traversals, allowing queries to search multiple "hops" downstream (e.g., -[:DependsOn]->{1,3}) to identify exactly how many businesses and jobs are indirectly exposed to a closure.

Numbered Explanation of What is Created

  1. Project Configuration & Dataset Creation: Initializes a BigQuery dataset (a4i_econ) and provisions an Enterprise-tier reservation capable of running Graph queries.
  2. Toy Data Loading: Generates and loads an illustrative 12-business dataset to demonstrate the limitations of simple ranking versus the advantages of a network traversal approach.
  3. Property Graph Definition: Creates the ToyBlock graph in BigQuery, declaring the node and edge tables, primary keys, labels, and property schemas without duplicating the underlying data.
  4. Graph Query Execution: Runs a GQL (Graph Query Language) query to traverse the network, illustrating the cascading impact of a business failure up to 3 hops away.
  5. Real Data Ingestion: Connects to the San Francisco Socrata open data portal to fetch real, live business registrations and limits the scope to a specific commercial corridor for actual analysis.
